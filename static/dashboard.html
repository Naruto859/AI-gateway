Failure Diagnosis 7 rules

How the gateway decides WHOSE fault a failed request was: the proxy, the endpoint, or the request itself. Getting this wrong is what caused retry storms and endpoints being dropped for no reason. All ON is the measured-correct setting — turn one OFF only to compare behaviour.

Trust status over content-type
Some providers reject a streaming request with HTTP 400 but still label it as a stream. ON = believe the 400. OFF = the old behaviour, where that error was reported as a broken proxy and the real reason never reached the log.
Match number rules on status only
Failover rules like 502 or 401 are status codes. ON = compare them to the response status. OFF = search them anywhere in the reply, where a provider's request id such as …518501558… accidentally matched "501" and made identical errors behave differently each time.
Stop retrying an oversized request
ON = when a provider says the conversation is too long, skip its remaining proxies and keys and move straight to the next provider. OFF = keep resending the same oversized message, which measured 15 attempts and 465 seconds for one request.
Blame the proxy, not the endpoint
ON = connection errors, read errors and blocked pages count against the exit IP, so a bad network never retires a healthy provider. OFF = old behaviour, where two unlucky proxies dropped a working endpoint and the retry limit was never reached.
Treat a refusal as an answer
When the model declines to reply it sends a valid but empty answer. ON = deliver it. OFF = call it a broken stream and retry it on every proxy and provider — measured 11 attempts and 75 seconds for an answer that arrived on the first try.
Keep the request method
ON = an info request such as the model list is sent upstream as GET. OFF = old behaviour, sent as POST, so every provider answered "Invalid URL" 404.
Strict bot-block detection
ON = only a real challenge page counts as blocked. OFF = any web page counts, which labelled ordinary server error pages as "WAF" and hid what actually failed. Cloudflare in front of a provider is normal and is not a block.
